# Stealth-чекап

> Русский перевод. Английский оригинал: [stealth-checkup.md](stealth-checkup.md).

Повторяемая процедура, которая определяет, допустим ли с точки зрения stealth выпуск сборки движка Ombra, сборки приложения или изменения SDK.

Это не обещание, что браузер невозможно обнаружить. Детект — движущаяся цель: он зависит от сайта, региона, репутации IP, истории аккаунта, версии браузера, версии детектора и согласованности профиля. Чекап нужен, чтобы заменить анекдоты **измерениями в зафиксированных условиях** и поймать регрессии раньше пользователей.

Метод во многом опирается на два открытых проекта, которые правильно сделали скучную часть: [stealth-browser-mcp](https://github.com/vibheksoni/stealth-browser-mcp), чей еженедельный мультиплатформенный бенчмарк и модель статусов — хороший шаблон, и ранние README [CloakBrowser](https://github.com/CloakHQ/CloakBrowser), где вместо расплывчатых заявлений опубликована таблица детекторов. Мы сохраняем воспроизводимость и отказываемся от гарантий.

## 1. Принципы

1. **Измеряйте, а не утверждайте.** Каждое утверждение в заметках о релизе должно указывать на отчёт с ID запуска.
2. **Фиксируйте условия.** ОС, версия движка, майлстоун Chromium, режим, страна прокси, хеш seed, версии детекторов и дата. Результат без них — не результат.
3. **Отделяйте дефекты движка от дефектов клиента.** Утечка, вызванная внешней конфигурацией Playwright/Puppeteer, — не отказ движка, но это по-прежнему видимый пользователю отказ, и его нужно задокументировать.
4. **Гейт по регрессиям, а не по абсолютному совершенству.** Некоторые цели ожидаемо деградируют на CI без GPU или за прокси. Базлайн кодирует то, что известно и принято.
5. **Ограничивайте срок исключений.** У известного пробела есть владелец и дата пересмотра. Тихие бессрочные исключения — вот с чего начинается эрозия stealth.
6. **Скрывайте данные агрессивно.** Никаких учётных данных прокси, полных IP, cookies, токенов или данных профиля в отчётах и артефактах CI.

## 2. Слои детекта

Чекап покрывает шесть слоёв. У каждого слоя свой владелец и свой режим отказа.

| Слой | Что измеряется | Владелец | Типичные цели |
|---|---|---|---|
| **L0 Транспорт** | IP выхода, DNS, WebRTC, TLS, HTTP/2, заголовки | Движок + прокси-путь приложения | TrackMe, страницы утечки IP/WebRTC, эхо заголовков |
| **L1 Идентичность** | UA, Client Hints, платформа, GPU, экран, шрифты, локаль, часовой пояс | Движок | Локальная проба, Sannysoft, Intoli |
| **L2 Отпечаток** | Canvas, WebGL, аудио, client rects, голоса, медиаустройства | Движок | CreepJS, FingerprintJS, BrowserScan, Pixelscan |
| **L3 Автоматизация** | WebDriver, артефакты CDP, внедрённые скрипты, биндинги, стек-трейсы | Движок + SDK/помощник | rebrowser, brotector, botd, локальная проба |
| **L4 Поведение** | Доверенный ввод, порядок событий, траектория мыши, набор текста, прокрутка, тайминги | Humanize движка + клиент автоматизации | Страница достоверности ввода, потоки CAPTCHA, Cloudflare smoke |
| **L5 Согласованность** | Стабильность seed, согласие main/worker/iframe, перезагрузки, паритет между SDK | Движок + SDK | Локальная проба в разных контекстах |

Профиль может пройти L1 и провалить L0, потому что выход прокси не совпадает с часовым поясом. Он может пройти L2 и провалить L3, потому что помощник включил `Runtime`. Слои оцениваются раздельно намеренно.

## 3. Модель угроз

Детекторы комбинируют сигналы; ни одна отдельная проверка не является решающей.

- **Серверная сторона:** репутация IP и ASN, TLS JA3/JA4, отпечаток HTTP/2, порядок и регистр заголовков, поведение cookies, тайминги запросов, согласованность геолокации.
- **Клиентский JavaScript:** поверхность `navigator`, Client Hints, хеши canvas/WebGL/аудио, шрифты, разрешения, кандидаты WebRTC, квота хранилища, артефакты CDP, стек-трейсы ошибок, `isTrusted` у событий.
- **Поведенческие:** траектории указателя, интервалы click down/up, каденция набора текста, физика прокрутки, смены фокуса, тайминги навигации, взаимодействие с CAPTCHA.
- **Межзапросные:** переиспользование отпечатка между сессиями, переключение профилей, история cookies и локали, противоречия между визитами.

Противник — не одна страница. Продакшен-антибот коррелирует все четыре группы и может выдать челлендж повторно после успешного прохождения. Поэтому чекап считает один зелёный скриншот свидетельством ровно для одного запуска, а не для релиза.

## 4. Предусловия

Перед запуском любой цели:

- [ ] Сборка движка — ровно тот артефакт, что тестируется, зафиксированный по версии и SHA-256.
- [ ] Сборка приложения зафиксирована по версии; Local API слушает loopback, другие клиенты не подключены.
- [ ] Существует отдельный тестовый профиль с фиксированным seed и без персональных данных.
- [ ] На профиле настроен прокси, и страна выхода зафиксирована.
- [ ] Часовой пояс, локаль и WebRTC настроены следовать выходу прокси, если тест явно не проверяет ручные значения.
- [ ] Режим headed или headless зафиксирован. Детекторы ведут себя по-разному; для полного прохода нужны оба режима.
- [ ] Расширения отключены, кроме тестового расширения, если запуск измеряет расширения.
- [ ] Нет подключённого дебаггера, окна DevTools или второго клиента автоматизации.
- [ ] У машины есть работающий GPU для целей, требующих GPU. CI без GPU использует программный WebGL и получает `DEGRADED` только на проверках рендерера.
- [ ] Тестовые аккаунты и целевые сайты авторизованы для такого тестирования.

Записывайте всё это в заголовок отчёта. Если условие неизвестно, запуск получает `UNREACHABLE` для целей, которые от него зависят.

## 5. Модель статусов

| Статус | Значение | Влияние на релиз |
|---|---|---|
| **PASS** | Все проверки в цели прошли | Идёт в зачёт гейта |
| **DEGRADED** | Провалились только известные задокументированные второстепенные проверки | Допускается только с записью `known_gap`: причина, владелец, срок |
| **FAIL** | Провалилась хотя бы одна критическая проверка | Блокирует релиз |
| **UNREACHABLE** | Цель не удалось загрузить или измерить | Перезапуск; два отказа подряд блокируют или требуют исключения от владельца |

Критические проверки — те, что напрямую выявляют автоматизацию или ломают согласованность:

- `navigator.webdriver` истинно.
- Срабатывает утечка CDP (`runtimeEnableLeak`, `exposeFunctionLeak`, `pwInitScripts`, `sourceUrlLeak`).
- Внедрённый скрипт или биндинг виден странице.
- IP хоста виден через HTTP, STUN или TURN.
- JA4 или HTTP/2 не совпадают с Chromium движка.
- Обнаружен маркер headless или «ложь» в отпечатке.
- Один и тот же seed даёт разные отпечатки между запусками.
- UA, Client Hints, платформа и GPU противоречат друг другу.

Всё остальное по умолчанию второстепенно и должно классифицироваться в определении цели, а не в момент составления отчёта.

Волатильные значения фиксируются, но не решают вердикт: ML-оценки FingerprintJS, проценты CreepJS, которые меняются между запусками, флаги прокси/VPN при намеренном использовании прокси и вердикты ad-tech, зависящие от истории аккаунта.

## 6. Цели и гейты

ID стабильны и используются в отчётах и базлайнах.

| ID | Цель | Слой | Что ловит | Гейт |
|---|---|---|---|---|
| `L0-01` | Аудит флагов запуска | L0 | Флаги автоматизации, sandbox или переопределений в реальной командной строке | Нет запрещённых флагов |
| `L0-02` | Утечка IP и WebRTC | L0 | IP хоста через HTTP, STUN или TURN | Только IP выхода |
| `L0-03` | TLS и HTTP/2 | L0 | JA3N, JA4, хеш Akamai, различия шифров и расширений | Совпадение с эталонным Chromium |
| `L1-01` | Локальная проба отпечатка | L1 | WebDriver, объект chrome, плагины, разрешения, UA-CH, экран, шрифты, часовой пояс | Все критические проверки проходят |
| `L1-02` | Sannysoft | L1 | Классические признаки headless и автоматизации | Все строки зелёные |
| `L1-03` | Intoli headless test | L1 | Старые маркеры headless и согласованность UA | Все строки проходят |
| `L1-04` | Согласованность Client Hints | L1 | UA vs `Sec-CH-UA`, платформа, архитектура, разрядность | Нет противоречий |
| `L2-01` | CreepJS | L2 | Глубокий фингерпринтинг, проценты headless/stealth, «ложь» | Нет секции `lie`; нет маркера headless |
| `L2-02` | FingerprintJS / botd | L2 | Детект ботов и стабильность посетителя | `bot: false`; стабильный visitor ID для одного и того же seed |
| `L2-03` | BrowserScan | L2 | Детект ботов, маскировка, прокси, выводы по часовому поясу | `NoDetection`; нет вывода о бот-контроле |
| `L2-04` | Pixelscan | L2 | Поведение автоматизации, маскировка, WebRTC, сигналы прокси | Нет вердикта об автоматическом поведении; флаги утечек пусты |
| `L2-05` | Демо Fingerprint.com | L2 | Сигналы ботов и вмешательства в код | `not_detected`; `anti_detect_browser: false` |
| `L3-01` | Детектор ботов rebrowser | L3 | Утечки `Runtime.enable`, биндинга, init-скрипта, source URL | Нет утечек |
| `L3-02` | brotector | L3 | Отпечатки CDP и автоматизации | Нет обнаружений |
| `L3-03` | Проба init-скриптов и стеков | L3 | Видимые инъекции, аномалии `toString`, стек-трейсы | Нет артефактов |
| `L3-04` | Аудит команд CDP | L3 | Домены и команды, используемые клиентом | Нет `Runtime.enable`, `Debugger`, `Log` |
| `L4-01` | Достоверность ввода | L4 | Синтетические события, отсутствие `isTrusted`, неверный порядок событий | Все события доверенные и в правильном порядке |
| `L4-02` | Трассы humanize | L4 | Клики-телепорты, линейный набор текста, мгновенная прокрутка | В пределах записанных человеческих диапазонов |
| `L4-03` | Поток CAPTCHA | L4 | Детект, тайминги, поведение в ручном режиме | Переходы состояний соответствуют политике |
| `L4-04` | Smoke живого челленджа | L0–L4 | Cloudflare, Queue-it или продакшен-челлендж | Проходит без ручного вмешательства; не гарантия |
| `L5-01` | Стабильность seed | L5 | Один seed — разная персона между запусками | Идентичные канонические хеши |
| `L5-02` | Согласие контекстов | L5 | Main frame vs worker vs iframe vs cross-origin | Одинаковые значения |
| `L5-03` | Стабильность перезагрузки | L5 | Сброс шума, дрейф canvas, изменения хранилища | Стабильные хеши |
| `L5-04` | Паритет между SDK | L5 | Специфичное для SDK поведение запуска или CDP | Идентичные хеши для одного профиля |

### Заметки по целям

**L0-01 — Флаги запуска.** Смотрите на фактическую командную строку процесса движка, а не на намерения SDK. Запрещены: `--enable-automation`, `--disable-blink-features=AutomationControlled`, `--headless=old`, `--no-sandbox` на хосте, который поддерживает sandbox, `--remote-debugging-port` с фиксированным публичным портом, переопределения `--user-agent` и любой флаг, который приложение не собиралось передавать. Реальная командная строка движка — источник истины.

**L0-02 — IP и WebRTC.** Проверяйте через HTTP, STUN-страницу и TURN-релей. Профиль за прокси не должен раскрывать IP хоста ни одним путём. Прямой профиль может показывать собственный IP; это не утечка. Фиксируйте страну выхода и сравнивайте её с часовым поясом и локалью.

**L0-03 — TLS и HTTP/2.** Используйте локальный инстанс TrackMe или `tls.peet.ws`. Сравнивайте JA3N, JA4 и хеш Akamai HTTP/2 с настоящим Chrome того же майлстоуна. Расхождение обычно означает не-Chromium клиент, прокси с терминацией TLS или сборку с изменённым сетевым стеком.

**L1-01 — Локальная проба.** Держите в комплекте страницу, которая работает без доступа к сети. Она должна покрывать `navigator.webdriver`, `window.chrome`, плагины, разрешения, UA-CH, число аппаратных потоков, память устройства, экран и вьюпорт, глубину цвета, часовой пояс, языки, вендор и рендерер WebGL, шрифты и хеш canvas. Это первая цель, которую запускают, и первая, которая падает, когда сборка неверна.

**L1-02 / L1-03 — Публичные наборы проверки идентичности.** Sannysoft и Intoli стары, но всё ещё ловят небрежные регрессии. Сами по себе они недостаточны; это дешёвые и стабильные smoke-тесты.

**L2-01 — CreepJS.** Относитесь к процентам как к данным тренда. Гейт — наличие секции «лжи» или явного маркера headless, а не конкретный trust score. В некоторых сборках CreepJS использует облачные вычисления; фиксируйте, была ли оценка доступна.

**L2-02 — FingerprintJS / botd.** По возможности запускайте локальный бандл botd, потому что демо-страница меняется. Visitor ID должен быть стабильным для одного и того же seed и должен меняться при смене seed. Стабильный ID на разных seed — это баг генератора персон, а не победа.

**L2-03 / L2-04 / L2-05 — Коммерческие детекторы.** Это сервисы с состоянием на момент проверки. Фиксируйте версию детектора или хеш страницы, регион и сырой вердикт. Флаг `Proxy detected` ожидаем при использовании прокси и не должен оцениваться как отказ; флаг `Masking detected` — это отказ. ML-оценка Fingerprint.com волатильна и записывается только как данные.

**L3-01 / L3-02 — Утечки CDP.** Запускайте локальные бандлы rebrowser и brotector. Критические проверки — `runtimeEnableLeak`, `exposeFunctionLeak`, `navigatorWebdriver`, `pwInitScripts` и `sourceUrlLeak`. Если сам клиент автоматизации вызывает `Runtime.enable`, запуск должен отличить это от дефекта движка. Предпочтительная конфигурация клиента вообще не трогает этот домен.

**L3-03 — Проба init-скриптов и стеков.** Загрузите страницу, которая проверяет `Function.prototype.toString`, `Error.prepareStackTrace`, source URL скриптов и неожиданные глобалы. Любой внедрённый помощник должен быть невидим или не существовать. Автоматизация приложения Ombra использует изолированный мир с именем `ombra`; видимый мир или глобальный биндинг — это отказ.

**L3-04 — Аудит команд CDP.** Поставьте логирующий WebSocket-прокси между клиентом автоматизации и `data.ws.puppeteer` или используйте протокольный лог клиента. Записывайте каждый домен и метод. `Runtime.enable`, `Debugger.enable`, `Log.enable`, `Page.addScriptToEvaluateOnNewDocument` и `Target.setAutoAttach` с неожиданными фильтрами — красные флаги. Этот аудит ловит регрессии SDK раньше, чем их заметит детектор.

**L4-01 — Достоверность ввода.** Используйте страницу, которая записывает события указателя, мыши, клавиатуры и фокуса с `isTrusted`, таймстампами, координатами и порядком. Корректный клик — это последовательность `mouseMoved`, затем `mousePressed`, `mouseReleased`, с правдоподобными таймингами. Корректное нажатие клавиши несёт `key`, `code`, `keyCode` и, где уместно, данные композиции. `element.click()` и прямое присваивание значения эту цель не проходят.

**L4-02 — Трассы humanize.** Сравнивайте записанные трассы с огибающими персоны движка: скорость, распределение пауз, кривизна траектории, перелёт, затухание прокрутки. Гейт — не «выглядит по-человечески» на скриншоте, а «укладывается в записанную огибающую для этого пресета».

**L4-03 — Поток CAPTCHA.** Только для профилей с включённым модулем. Проверьте детект, переходы состояний, бюджет времени, лимит попыток, паузу в ручном режиме и то, что неудачное решение не оставляет профиль в зависшем состоянии. Эта цель не утверждает долю успешных решений.

**L4-04 — Smoke живого челленджа.** Прогоните один-два публичных челленджа, например `nowsecure.nl`, в регионе и на IP, которые записаны в отчёте. Считайте ручные взаимодействия и время до прохождения. Это smoke-тест, а не жёсткий гейт: политика сайта, репутация IP и версия челленджа меняются без предупреждения. Регрессия важна только тогда, когда тот же сайт проходил раньше на том же раннере и том же выходе.

**L5-01 — Стабильность seed.** Запустите один и тот же профиль трижды. Канонизируйте отпечаток в стабильный JSON-объект (отсортированные ключи, исключённые волатильные значения) и захешируйте его. Все три хеша должны совпасть. Смените seed и убедитесь, что хеш изменился.

**L5-02 — Согласие контекстов.** Одинаковые значения canvas, WebGL, аудио и часового пояса должны возвращаться из главного фрейма, выделенного worker'а, same-origin iframe и cross-origin iframe. Значение, зависящее от контекста, — сигнал детекта, даже если каждое значение по отдельности выглядит правдоподобно.

**L5-03 — Стабильность перезагрузки.** Перезагрузите страницу, уйдите со страницы и вернитесь, восстановите закрытый профиль. Шум не должен сбрасываться на каждый документ, а квота хранилища не должна скакать.

**L5-04 — Паритет между SDK.** Прогоните один и тот же профиль и seed через Python, Node.js и хотя бы один SDK на компилируемом языке. Канонические хеши должны совпасть. Различие означает, что SDK добавляет флаг, команду CDP или опцию запуска, которых добавлять не должен.

## 7. Ранбук

### Шаг 0 — Заморозить входные данные

```text
engine_version:   151.0.7922.108 (build SHA-256)
app_version:      <version>
contract_version: 0.1.0
os:               macOS 15.x arm64 / Windows 11 x64 / Ubuntu 24.04 x64
mode:             headed | headless
proxy_country:    <ISO country>
seed_hash:        sha256(seed) — never the raw seed in public reports
detectors:        rebrowser <sha>, brotector <sha>, botd <version>, ...
```

### Шаг 1 — Харнесс движка

Сначала прогоните QA-набор движка. Это единственное место с полным доступом к флагам процесса, логам CDP и внутренностям профиля.

```bash
# Из репозитория движка.
scripts/mac/qa.sh --detectors \
  --proxy socks5://127.0.0.1:10808 \
  --persona macos-full \
  --mode both \
  --report-dir qa/out/checkup-$(date +%F)
```

Харнесс пишет `report.json` и `report.md`. Сохраняйте оба; JSON — машиночитаемый источник, Markdown — для людей.

### Шаг 2 — Проход по SDK и клиенту

SDK не меняет движок, но может изменить опции запуска и CDP-клиент. Прогоните один и тот же профиль через каждый тестируемый SDK и соберите:

- реальную командную строку движка;
- аудит команд CDP;
- вывод локальной пробы;
- скриншоты и сырой текст публичных целей.

Conformance-раннер для этого шага запланирован в `conformance/stealth/`; пока его нет, используйте харнесс движка для движка и ручную матрицу ниже для клиента. Раннер не должен быть отдельной реализацией проверок — он использует те же кейсы и ту же схему отчёта.

### Шаг 3 — Собрать артефакты

По каждой цели: статус, текст отказа, скриншот, сырой DOM или JSON, версия детектора и таймстамп. Храните артефакты в каталоге запуска, ключом которого служит run ID. Вырезайте учётные данные и полные IP в момент захвата, а не в момент публикации.

### Шаг 4 — Сравнить с базлайном

Базлайн индексируется по `target × platform × mode × engine major`. Сравнивайте:

- цель, которая проходила раньше и падает сейчас → регрессия, блок;
- цель, которая падала раньше и проходит сейчас → уберите известный пробел;
- новый флаг у проходящей цели → разберитесь, даже если вердикт не изменился;
- изменение версии инструмента → пометьте сравнение недействительным и перестройте базлайн.

### Шаг 5 — Подписать

Отчёт подписывает владелец релиза, а не тот, кто его запускал. Подпись означает: условия зафиксированы, артефакты существуют, гейты применены, а у каждого исключения есть владелец и срок действия.

## 8. Чеклист по сигналам

Используйте это как ручную матрицу, когда автоматический раннер недоступен.

### L0 — Транспорт

| Проверка | Ожидание | Если падает |
|---|---|---|
| IP выхода по HTTP | Выход прокси | Прокси не применён к профилю или прямой запрос ушёл мимо |
| STUN-кандидат | Выход прокси или нет кандидата | WebRTC обходит прокси |
| TURN-релей | Выход прокси | UDP-путь раскрывает хост |
| Разрешение DNS | Через путь прокси | Утечка DNS или split tunneling |
| JA3N / JA4 | Совпадает с эталонным Chromium | Прокси с терминацией TLS, не-Chromium клиент, изменённый сетевой стек |
| Хеш Akamai HTTP/2 | Совпадает с эталонным Chromium | То же, что выше |
| Порядок заголовков | Как у Chromium | Прокси или SDK переписал заголовки |
| Часовой пояс vs выход | Согласован | `automatic_timezone` выключен или неверная гео прокси |
| Локаль vs выход | Согласована | Ручной язык переопределяет профиль |

### L1 — Идентичность

| Проверка | Ожидание | Если падает |
|---|---|---|
| `navigator.webdriver` | `false` | Нет патча движка или `--enable-automation` |
| `window.chrome` | Объект с runtime | Не Chromium или урезанная сборка |
| Плагины | Пять PDF-плагинов | Headless-сборка или урезанный профиль |
| Разрешения | `prompt` для уведомлений | Дефолты автоматизации или плохое переопределение |
| UA | Без `Headless`, версия совпадает с движком | Старый флаг или переопределение клиента |
| Бренды UA-CH | Содержат бренд Chromium движка и мажорную версию | UA и Client Hints расходятся |
| `navigator.platform` | Совпадает с ОС персоны | Несоответствие генератора персон или ОС |
| Число аппаратных потоков | Совпадает с персоной | Утечка значения хоста |
| Память устройства | Совпадает с персоной | Утечка значения хоста |
| Экран / avail / DPR | Совпадает с персоной | Переопределение вьюпорта в Playwright |
| Глубина цвета | 24 или 30, согласована | Дефолт headless |
| Шрифты | Набор согласован с персоной | Утечка шрифтов хоста или seed проигнорирован |
| Вендор / рендерер WebGL | Согласован с GPU персоны | Программный рендерер или утечка GPU хоста |

### L2 — Отпечаток

| Проверка | Ожидание | Если падает |
|---|---|---|
| Хеш canvas | Стабилен для seed, различается между seed | Шум на вызов или отсутствие seed |
| Хеш изображения WebGL | Стабилен для seed | То же, что выше |
| Аудиоотпечаток | Стабилен для seed | То же, что выше |
| Client rects | Стабильны для seed | То же, что выше |
| Голоса | Согласованы с персоной | Утечка голосов хоста |
| Медиаустройства | Согласованы с персоной | Утечка устройств хоста |
| Квота хранилища | Согласована с персоной | Дефолтное или хостовое значение |
| Секции `lie` (CreepJS) | Отсутствуют | Подменённое свойство детектируется |
| Флаги маскировки | Отсутствуют | Детектор видит сам патч |

### L3 — Автоматизация

| Проверка | Ожидание | Если падает |
|---|---|---|
| Использован `Runtime.enable` | Нет | Клиент автоматизации или SDK включил его |
| Утечка `exposeFunction` | Нет | Биндинг виден |
| Утечка init-скрипта | Нет | `addScriptToEvaluateOnNewDocument` виден |
| Утечка source URL | Нет | У внедрённого скрипта есть file URL |
| `navigator.webdriver` | `false` | См. L1 |
| Глобалы `cdc_` | Отсутствуют | Подключён Chromedriver |
| Изолированный мир виден | Нет | Мир помощника раскрыт |
| Артефакты автоаттача CDP | Отсутствуют | Клиент подключился к каждой цели |
| Домены Console / Log | Не включены | Клиент включил их для отладки |

### L4 — Поведение

| Проверка | Ожидание | Если падает |
|---|---|---|
| События клика | Доверенные, упорядоченные, правдоподобные тайминги | DOM `.click()` или синтетическое событие |
| Траектория мыши | Кривая, с паузами и перелётом | Телепорт к цели |
| Нажатия клавиш | `key`, `code`, `keyCode`, композиция | Только `insertText` или неверная раскладка |
| Вставка | Хоткей движка или доверенная вставка | Запись в `navigator.clipboard` из JS |
| Прокрутка | Wheel-события с затуханием | Прыжки через `scrollTo` |
| Фокус | Реальная последовательность focus и blur | Только программный фокус |
| Состояние CAPTCHA | Соответствует политике и таймингам | Модуль выключен или завис |

### L5 — Согласованность

| Проверка | Ожидание | Если падает |
|---|---|---|
| Один seed, три запуска | Идентичный канонический хеш | Персона не детерминирована по seed |
| Другой seed | Другой хеш | Seed игнорируется |
| Main vs worker | Идентичные поверхности | Поверхность пропатчена только в главном мире |
| Main vs iframe | Идентичные поверхности | Патч не применяется к iframe |
| Cross-origin iframe | Идентичные поверхности | Патч зависит от origin |
| Перезагрузка | Стабильные хеши | Шум сбрасывается на каждый документ |
| Перезапуск профиля | Стабильные хеши | Персона генерируется заново |
| Между SDK | Идентичные хеши | SDK добавляет флаги или вызовы CDP |

## 9. Отчётность

Отчёты — сначала JSON, потом Markdown. Схема лежит в [conformance/schema/report.schema.json](../conformance/schema/report.schema.json). Минимальный отчёт:

```json
{
  "run_id": "2026-11-16-macos-arm64-001",
  "started_at": "2026-11-16T09:00:00Z",
  "operator": "engine-qa",
  "sdk": { "name": "python", "version": "0.1.0" },
  "engine": { "version": "151.0.7922.108", "sha256": "…" },
  "environment": {
    "os": "macOS 15.7 arm64",
    "mode": "headed",
    "proxy_country": "DE",
    "seed_hash": "sha256:…"
  },
  "targets": [
    {
      "id": "L1-01",
      "status": "PASS",
      "failures": [],
      "artifacts": ["artifacts/L1-01/probe.json"]
    },
    {
      "id": "L2-03",
      "status": "DEGRADED",
      "failures": ["Proxy detected (expected: proxy in use)"],
      "known_gap": { "owner": "engine", "reason": "proxy flag is expected", "expires": "2026-12-31" }
    }
  ],
  "verdict": "PASS_WITH_GAPS"
}
```

Правила:

- `verdict` — это `PASS`, `PASS_WITH_GAPS`, `FAIL` или `INCOMPLETE`.
- Цель со статусом `FAIL` делает вердикт `FAIL`.
- Обязательная цель со статусом `UNREACHABLE` держит вердикт `INCOMPLETE` до перезапуска.
- `known_gap` обязателен для `DEGRADED`.
- Пути артефактов относительны каталога запуска.
- Сырой seed не сохраняется никогда. Хеша достаточно для сравнения запусков.

## 10. CI и регрессии

Еженедельная матрица, адаптированная из бенчмарка stealth-browser-mcp:

| Измерение | Значения |
|---|---|
| ОС | macOS arm64, Windows x64, Ubuntu x64 |
| Режим | headed, headless |
| Chromium | текущий stable, предыдущий майлстоун |
| Прокси | прямой, один резидентный выход |
| SDK | Python, Node.js и один компилируемый язык за ротацию |

Что делает джоб:

1. Собирает или устанавливает тестируемый артефакт движка.
2. Сначала запускает локальную пробу и аудит CDP; падает быстро.
3. Запускает публичные цели с ограниченным таймаутом.
4. Пишет `report.json` и публикует его как артефакт.
5. Сравнивает с `baseline.json` для того же ключа.
6. Открывает issue с меткой `stealth-regression`, когда падает цель, проходившая раньше.
7. Никогда не открывает issue для `UNREACHABLE`; он повторяет попытку один раз, затем сообщает `INCOMPLETE`.

Правила, специфичные для CI:

- Linux-раннеры без GPU сообщают программный WebGL. Это известный `DEGRADED` на проверках рендерера, а не блокер релиза.
- Публичные сервисы ограничивают частоту запросов и меняются без предупреждения. Предпочитайте локальные бандлы для гейтов, а публичные цели считайте smoke-тестами.
- Версии инструментов закреплены в отчёте. Если инструмент обновился, базлайн недействителен до перестройки.
- Секреты внедряются в рантайме и никогда не пишутся в артефакты. Логи вычищаются от URL прокси и IP.

## 11. Триаж

| Симптом | Вероятная причина | Исправление |
|---|---|---|
| `navigator.webdriver === true` | Нет патча, `--enable-automation`, chromedriver | Пересоберите движок, проверьте флаги, уберите драйвер |
| `runtimeEnableLeak` | Клиент включил `Runtime` | Используйте конфигурацию клиента, которая этого не делает, или пропатчьте клиент |
| `pwInitScripts` / `sourceUrlLeak` | Init-скрипт, внедрённый клиентом | Уберите `addScriptToEvaluateOnNewDocument`; используйте humanize движка |
| Хеш canvas меняется на каждый вызов | Шум применяется на вызов | Задавайте шум на профиль, а не на документ |
| Одинаковый canvas на разных seed | Патч игнорирует seed | Почините путь seed в движке |
| Программный рендерер WebGL | Нет GPU, headless CI, `--disable-gpu` | Ожидаемо на CI; для релизных прогонов используйте хост с GPU |
| Несовпадение часового пояса | `automatic_timezone` выключен, неверная гео прокси | Включите автоопределение или исправьте профиль |
| Реальный IP в WebRTC | Прокси обойдён, утечка UDP, фолбэк на TURN | Исправьте путь прокси; блокируйте UDP вне прокси |
| Несовпадение JA4 | TLS-прокси, не-Chromium клиент, изменённый сетевой стек | Используйте прокси в режиме pass-through и настоящий движок |
| Шрифты с хоста | Seed не применён или шрифты грузятся из ОС | Проверьте модель шрифтов и персону |
| Красный WebGL в Sannysoft | Программный рендерер | Хост с GPU; это не дефект кода |
| Цикл Cloudflare | Репутация IP, cookies, headless, поведение | Смените выход, очистите профиль, запустите в headed, проверьте ввод |
| CAPTCHA не детектится | Модуль выключен, несовпадение сборки, неподдерживаемый тип задания | Включите модуль; зафиксируйте неподдерживаемый тип |
| Профиль закрывается после последней вкладки | Ожидаемое headed-поведение, когда скрипт закрывает все вкладки | Оставьте вкладку открытой или запускайте headless |
| `conflict` при удалении | Профиль запущен | Сначала остановите |
| Таймаут запуска | Приложение занято, движок отсутствует, лицензионный слот | Проверьте приложение, установку движка и лицензию; затем остановите профиль |

## 12. Что этот чекап не покрывает

- Проприетарная скоринговая модель конкретного сайта. Измерить её может только сам сайт.
- Репутация аккаунта, cookies и история браузера. Идеальный отпечаток на сгоревшем аккаунте всё ещё падает.
- Юридическое или договорное разрешение автоматизировать цель.
- Долгосрочный дрейф. Проход действителен для зафиксированной сборки и даты, а не навсегда.
- Доля успешных решений CAPTCHA. Чекап проверяет состояние и политику, а не проценты успеха.

## 13. Уроки, перенятые из экосистемы

**Из stealth-browser-mcp**

- Используйте настоящий браузер семейства Chrome по CDP, а не драйвер, который сам себя выдаёт.
- Аудируйте реальную командную строку запуска, а не намерения обёртки.
- Проверяйте пред-документную инъекцию как возможность, а затем убедитесь, что продакшен-пути не оставляют артефактов.
- Отправляйте ввод через доверенные события CDP; держите отдельный путь для крупной вставки.
- Держите поверхность инструмента маленькой. Их режим `--xpool-safe` отключает CDP-функции-инструменты, потому что `Runtime.enable` — это риск; та же логика применима к помощникам SDK.
- Публикуйте модель статусов и еженедельную матрицу и открывайте issue о регрессиях автоматически.
- Говорите «измерения, а не гарантии».

**Из ранних версий CloakBrowser**

- Держите таблицу детекторов в README, с датой теста и версией браузера.
- Объясняйте механизм, а не только результат.
- Считайте гонку вооружений фактом и говорите, что происходит, когда детект развивается.
- Держите путь установки и первый пример короткими.

**Из QA движка Ombra**

- Отделяйте дефекты движка от дефектов тестового харнесса, прогоняя те же тесты на неизменённом Chrome.
- Держите известные пробелы в реестре с причиной и ID патча и роняйте проверку, когда известный пробел начинает проходить.
- Запускайте детекторы в дефолтном контексте движка, а не в свежем инкогнито-контексте.
- Фиксируйте версии инструментов и перестраивайте базлайны, когда они меняются.
- Сравнивайте с эталонным движком на том же профиле, вместо того чтобы спорить по чеклисту.
